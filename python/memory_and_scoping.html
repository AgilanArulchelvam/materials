01 — Foundations

Mutable vs. immutable objects

A Python variable is a name bound to an object, not a container that holds a value directly. When you write y = x, you're not copying data — you're pointing a second label at the exact same box in memory.

The only thing that changes the picture is whether the object itself can be edited in place:

Immutable (can't change in place)Mutable (can change in place)
int, float, bool, str, tuple, frozenset, bytes list, dict, set, bytearray, most custom classes

"Immutable" doesn't mean the name can't be reassigned — it means the object that name points to can never be edited. Reassignment just points the name at a brand-new object.

02 — Where this actually bites you

Why mutability breaks default arguments

Default argument values are evaluated once — at function definition time — and stored on the function object itself (in __defaults__). Every call that doesn't supply that argument reuses the same object.

For immutable defaults (like 0 or None) this is invisible, because nothing can mutate them anyway. For a mutable default like [], it means every call is silently sharing — and potentially editing — the exact same list.

def add_item(item, basket=[]): # [] created ONCE, at def time basket.append(item) return basket add_item("apple") → ['apple'] add_item("banana") → ['apple', 'banana'] 😱 not a fresh basket!
WATCH THE SAME LIST GET REUSED

Every call below reuses the one list object created when the function was defined.

basket @ 0x7f3a1c []
Calls so far: 0

The fix

def add_item(item, basket=None): if basket is None: basket = [] # fresh list, made on EVERY call basket.append(item) return basket

Use None as the sentinel default and build the real mutable object inside the function body, so a brand-new object is created on every call instead of one shared across all of them.

03 — Name resolution

LEGB: how Python finds a name

Every time Python sees a name being read (not assigned), it searches a fixed sequence of namespaces — each one is really just a dictionary of name → object — stopping at the first match:

Local → Enclosing → Global → Built-in

x = "global x" def outer(): x = "enclosing x" def inner(): x = "local x" print(x) # found in Local — search stops immediately inner() outer() → local x

04 — Functions that remember

Closures

A closure happens when an inner function uses a variable from its enclosing function, and that inner function is then handed back out to the world (returned, stored, passed around). Normally a function's local variables die when it returns — but if an inner function still needs one, Python keeps it alive in a special cell object, tucked inside the inner function's __closure__ attribute.

def make_counter(): count = 0 # lives in a cell, not a normal stack frame def increment(): nonlocal count count += 1 return count return increment counter = make_counter() # make_counter() has already returned... counter() → 1 counter() → 2 ...but 'count' is still alive, held by the closure

The classic loop trap (late binding)

Closures capture the variable, not a frozen snapshot of its value at creation time. If that variable keeps changing (like a loop counter), every closure you made in that loop sees whatever the variable's value is by the time they're called — usually its final value.

funcs = [] for i in range(3): funcs.append(lambda: i) [f() for f in funcs] → [2, 2, 2] all three share the SAME i # fix: force capture by value using a default argument funcs2 = [] for i in range(3): funcs2.append(lambda i=i: i) # i=i binds NOW, as a local default [f() for f in funcs2] → [0, 1, 2]
05 — Rebinding across scopes

nonlocal vs global

By default, assigning to a name inside a function always creates a new local variable — Python never silently reaches outward to modify an existing one. global and nonlocal are explicit opt-ins that say "don't create a local — rebind the one that already exists out there."

KeywordTargetsRequires the name to already exist?
global xThe module's global namespace, no matter how deeply nested the function is.No — creates it in globals if missing.
nonlocal xThe nearest enclosing function scope (skips straight past global).Yes — raises SyntaxError at compile time if no enclosing scope defines it.
TOGGLE THE KEYWORD, SEE THE OUTCOME
count = 100 # global def outer(): count = 10 # enclosing def inner():     # (no keyword) count = count + 1 inner() print("outer's count:", count) outer() print("global count:", count)
06 — Flexible function signatures

*args and **kwargs

The * and ** operators do two opposite jobs depending on which side of a function call they appear on.

In a function definition (packing)In a function call (unpacking)
*Gathers extra positional args into a tuple named args.Spreads an iterable out into separate positional arguments.
**Gathers extra keyword args into a dict named kwargs.Spreads a dict out into separate keyword arguments.
def describe(*args, **kwargs): print("args:", args) print("kwargs:", kwargs) describe(1, 2, name="Rex", breed="Lab") args: (1, 2) kwargs: {'name': 'Rex', 'breed': 'Lab'} # --- unpacking on the CALL side --- nums = [4, 5, 6] info = {"name": "Milo", "breed": "Pug"} describe(*nums, **info) # same call as describe(4, 5, 6, name="Milo", breed="Pug")

Parameter ordering rule

def f(pos1, pos2, *args, kw_only1, kw_only2=None, **kwargs): ... # positional-or-keyword → *args → keyword-only → **kwargs

Anything listed after *args can only be passed by keyword — that's how Python defines "keyword-only" parameters.

Practice problems

Predict the output before you run each one mentally. Expand the solution only after you've committed to an answer.

Problem 1 · Mutability
a = [1, 2, 3] b = a c = a[:] b.append(4) c.append(5) print(a, b, c)
Show solution
a = [1, 2, 3, 4] b = [1, 2, 3, 4] c = [1, 2, 3, 5] b is the same object as a (append mutates it in place, visible through both names). c = a[:] makes a shallow COPY — a new list object — so mutating c never touches a or b.
Problem 2 · Default arguments
def tag(label, seen=[]): seen.append(label) return seen print(tag("a")) print(tag("b")) print(tag("c", [])) print(tag("d"))
Show solution
['a'] ['a', 'b'] ['c'] ['a', 'b', 'd'] The default list is created once at def time and reused across every call that doesn't pass its own list. Passing an explicit [] for "c" bypasses the shared default for that one call only — the shared list is untouched by that call, so the next call without an argument ("d") still appends to the original shared list.
Problem 3 · LEGB / UnboundLocalError
x = 10 def f(): print(x) x = 20 f()
Show solution
UnboundLocalError: local variable 'x' referenced before assignment Because x is assigned somewhere inside f() (x = 20), Python marks x as local for the WHOLE function body at compile time — including the print(x) line before the assignment. It never falls back to the global x.
Problem 4 · Closures + late binding
def make_multipliers(): return [lambda x: x * i for i in range(1, 4)] fns = make_multipliers() print([f(10) for f in fns])
Show solution
[30, 30, 30] All three lambdas close over the SAME variable i. By the time any of them are called, the list comprehension has finished and i's final value is 3, so every call computes 10 * 3. Fix with a default argument: lambda x, i=i: x * i
Problem 5 · nonlocal
def outer(): total = 0 def add(n): total += n # no nonlocal! return total return add adder = outer() print(adder(5))
Show solution
UnboundLocalError: local variable 'total' referenced before assignment total += n is shorthand for total = total + n, which is an assignment — so Python treats total as local to add(), and the read on the right-hand side happens before any local total exists. Fix by adding `nonlocal total` as the first line of add().
Problem 6 · *args / **kwargs forwarding
def logged(fn): def wrapper(*args, **kwargs): print(f"calling with {args}, {kwargs}") return fn(*args, **kwargs) return wrapper @logged def greet(name, greeting="Hi"): return f"{greeting}, {name}!" print(greet("Ada", greeting="Hello"))
Show solution
calling with ('Ada',), {'greeting': 'Hello'} Hello, Ada! wrapper packs whatever it's called with into args/kwargs, logs them, then UNPACKS them again with fn(*args, **kwargs) to forward the exact same call through to greet(). This pack-then-unpack pattern is how most decorators stay compatible with any wrapped function's signature.
Problem 7 · Mutable default meets closures (combo)
def make_appender(bucket=[]): def appender(x): bucket.append(x) return bucket return appender f1 = make_appender() f2 = make_appender() f1(1) f2(2) f1(3) print(f1(99) is f2(99))
Show solution
True f1 and f2 both close over the SAME default bucket list (created once at make_appender's definition time), so every call from either function appends to one shared list — f1(99) and f2(99) return the identical list object.
